## Contradictions found (for the owner to resolve — not fixed here)

1. **Identity vs ADR (most important).** `docs/adr/ADR-LIFEOS-001` (Accepted 2026-09-06) declares `my-assistant` a **retired/archived** accidental fork, names `lifeos` canonical, and requires dropping the "floating AI assistant / my-assistant" identity and re-framing as a `personal.*` capability pack for LOGOS. Yet README.md, CLAUDE.md, `pyproject.toml` description/keywords and the generated context files in **this same repo** still present it as the floating my-assistant product. Either this repo is not actually archived, or the recadrage follow-ups are outstanding. The generated docs still emit the old description.
2. **Python floor drift.** `pyproject.toml` requires `>=3.14`; CLAUDE.md "Key Constraints" says "Python 3.12+ minimum; target 3.14". Manifest is binding → 3.14.
3. **Container standard vs tooling.** chrysa canon (pointed to from CLAUDE.md) mandates containers-only, no host venv, multi-stage `production`+`dev` Dockerfiles. This repo installs on the host via `make install`/`dev` and ships only a single-stage `Dockerfile.test` (no app image, no compose). Partial compliance.
4. **Branch model.** CONTRIBUTING.md branches from `main` (with `no-commit-to-branch` on `main`); the standards core in CLAUDE.md also describes a `main` production / `develop` workspace model. This repo's contributor doc uses `main` only. Minor.
5. **Make target names.** README/CLAUDE examples reference `make dev` / `make run` / `make format`; the Makefile does define `dev`, `format`, `run`, plus `install`, `docker-test`, `typecheck`, `quality-gate-*` — consistent, but CONTRIBUTING says `make install` installs dev deps + hooks while the Makefile's `install` is runtime-only and `dev` is the one that installs hooks. Small inaccuracy in CONTRIBUTING.
